# Substitute Finder Application

A Spring Boot REST API application for managing sports game substitution requests. The application allows users to register and create substitution requests for games, storing data in AWS DynamoDB.

## 🎯 Features

- **User Management**: Register and manage user information (first name, last name, phone number, gender)
- **Game Management**: Create and manage game information (game ID, field number, time, number of substitutes, shirt color, list of substitutes)
- **Substitution Requests**: Create substitution requests linking users to games
- **AWS DynamoDB Integration**: Persistent data storage using Amazon DynamoDB
- **RESTful API**: Clean REST endpoints for interacting with the application

## 🛠️ Technology Stack

- **Java 17**
- **Spring Boot 3.1.5**
- **Spring Data DynamoDB**
- **AWS SDK for Java** (v2.20.109)
- **Amazon DynamoDB**
- **Maven** (Build tool)

## 📋 Prerequisites

Before running this application, ensure you have the following installed:

- **JDK 17** or higher
- **Maven 3.6+**
- **AWS Account** (for DynamoDB) or **DynamoDB Local** for local development
- (Optional) **DynamoDB Local** for local testing

## 🚀 Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/engr-muhammad-mansoor/substitute-finder-application.git
cd substitute-finder-application
```

### 2. Configure AWS Credentials

Copy the example properties file and configure your AWS credentials:

```bash
cp src/main/resources/application.properties.example src/main/resources/application.properties
```

Edit `src/main/resources/application.properties` and update the following:

```properties
amazon.aws.accessKey=your-access-key-here
amazon.aws.secretKey=your-secret-key-here
amazon.dynamodb.endpoint=http://localhost:8000/  # For local DynamoDB
# aws.region=us-west-2  # Uncomment for production AWS DynamoDB
```

**Important**: Never commit `application.properties` with real credentials. The `.gitignore` file is configured to exclude this file.

### 3. Set Up DynamoDB Tables

The application requires two DynamoDB tables:
- `UserTable` - Stores user information
- `GamesTable` - Stores game information

#### Option A: Using DynamoDB Local

1. Download and start DynamoDB Local:
   ```bash
   java -Djava.library.path=./DynamoDBLocal_lib -jar DynamoDBLocal.jar -sharedDb
   ```

2. Create the tables using AWS CLI or the DynamoDB console.

#### Option B: Using AWS Cloud

1. Create the tables in your AWS account with the following schema:
   - **UserTable**: Primary key `userId` (String)
   - **GamesTable**: Primary key `gameID` (String)

### 4. Build the Application

```bash
mvn clean install
```

### 5. Run the Application

```bash
mvn spring-boot:run
```

The application will start on `http://localhost:8080` by default.

## 📡 API Endpoints

### Create Substitution Request

**POST** `/sub-finder-application/subRequest`

Creates a new substitution request by registering a user and creating/updating a game entry.

**Request Body:**
```json
{
  "firstName": "John",
  "lastName": "Doe",
  "phoneNumber": "+1234567890",
  "gender": "Male",
  "gameId": "GAME-001"
}
```

**Response:**
```json
{
  "gameId": "GAME-001",
  "fieldNumber": "Field-1",
  "time": "10:00 AM",
  "numOfSubs": 2,
  "shirtColor": "Blue",
  "listOfSubs": ["user1", "user2"]
}
```

## 🔧 Configuration

### Application Properties

The application uses the following configuration properties:

- `amazon.aws.accessKey`: AWS access key ID
- `amazon.aws.secretKey`: AWS secret access key
- `amazon.dynamodb.endpoint`: DynamoDB endpoint (for local development)
- `aws.region`: AWS region (for production)

### DynamoDB Tables

- **UserTable**: Stores user information with auto-generated `userId`
- **GamesTable**: Stores game information with auto-generated `gameID`
